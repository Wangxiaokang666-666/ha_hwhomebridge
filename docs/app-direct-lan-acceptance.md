# 智慧生活 App 直连 LAN 验收（2026-10-21 至 22）

本页验收结果属于实验身份清理前的历史记录。2026-10-22 已按用户要求删除实验网关及残留子卡；这些旧配对目录不能再当作仍在线、仍有效的身份启动。清理结果见文末。

本轮只使用已配对的独立实验身份、实际 ARM HA 镜像和 `oh_single_` 虚拟实体。没有访问原 HA、部署组件、切换生产引擎或操作家庭灯光、米家自动化。原生 x86 主机仍缺少，不能把本轮 ARM 结果当作 x86 验收。

## 这次实际确认了什么

临时桥接已运行，独立 Linux 获得家庭 LAN 地址。MatePad 可以直接访问实验 Linux；SDK 使用其局域网接口，未经过 Mac 应用代理或 SSH/UDP 转发。

此前看到的离线卡属于已退役的 **A 组**，不能据此判断正在运行的 **B 组**离线。本轮在 App 的设备信息中精确核对 B 组根 SN 及 `effects-2` 子 SN，均与私有实验清单相同。B 组父网关在线，列表有 15 个子设备；预置离线卡仍隔离。只操作该组已核对身份的虚拟卡，没有按通用卡片名称猜测家庭设备。

| 验收项 | 本轮结果 | 实际证据与边界 |
| --- | --- | --- |
| App 的局域网发现 | 通过 | 物理 MatePad 发出 `cloudSetup`，实验 C SDK 单播应答；有效双向抓包有 24 条请求、24 条响应、4 个请求源端口收到对应响应。包含重传，不能解释为 24 次一一对应交换 |
| 冷启动后的首次空场景 LAN 控制 | 未通过 | SDK 的 WAN 通道隔离后只点击一次：零 HA 调用、零 C 确认、虚拟灯未变；没有观察到本地认证或控制请求 |
| 恢复 WAN 后的 App 云端对照 | 通过 | 同一已核对卡片单击开启，一次 `light.turn_on(effect=空场景)`、一次 C 接受和确认，约 1041 ms；其他虚拟实体不变 |
| 实际 HA 重启及 App 状态恢复 | 云端通过 | 新 HA 进程恢复同一条目、配对资料和虚拟状态，一个 SDK 所有者；App 显示空场景已启用 |
| 重启后的首次 App 控制 | 云端通过 | 单击关闭，一次 `light.turn_off`、一次 C 接受和确认，约 1065 ms；其他虚拟实体不变 |
| 平板 IPv4 外网受限后的控制 | 未通过 | 保留平板 IP，临时网关指向不转发流量的实验 Linux；LAN 探测成功、IPv4 外网探测失败。SDK WAN 同时隔离后单击一次，仍为零 HA 调用和 C 确认 |
| 平板完全断网条件 | 未建立 | IPv6 默认路由仍在，且 IPv6 外网探测成功；上一行只能算 IPv4 受限试验，不能算 App 全离线验收 |
| App LAN 服务读写与重启恢复 | 待补 | 未观察到 App 的 `ohLocalControl`、`.sys/sessMngr` 或 `e2eCtrl`；云端结果和发现应答均不能替代这一项 |

最初的冷启动失败完整保留，后来的云端对照不回填成“首次 LAN 成功”。恢复 Linux WAN、恢复平板 DHCP 后分别检查，没有迟到的 HA 写入。脱敏断言见[本轮实测记录](plans/app-direct-lan-runtime-validation.json)。原始截图、网络设置及报文元数据仅保存在私有实验目录。

## C 层排查的结论边界

App 的发现请求可被 SDK 正确解码，捕获的请求原样回放也能得到应答。物理 MatePad 的实际抓包确认 SDK 确实发送了响应，不能再把仅有接收方向的旧抓包当作“没有应答”。有效抓包使用双向捕获，范围是与测试平板有关、UDP 5683／5686／15686 的报文元数据；它不能排除其他端口或 IPv6 上的通信。

本轮没有接到 App 的本地认证或服务控制，因此不能把失败归因于 C 控制函数或 HMAC，也没有依据修改认证、放宽校验或增加重试。下一步需要比较原生旧 SDK 与 OpenHarmony 的配对后本地发现声明、协议入口及 App 发起协商的条件。此前按 `Content-Length` 读取 C 回环确认的修复继续保留；本轮云端对照得到正常确认，但不能据此认定历史失败或当前 LAN 缺口已经解决。

## 观察器与历史记录

App 观察夹具为每次 HA 启动分配 `acceptance_run_id`，在启动 HA／SDK **之前**记录审计和原生日志末尾，排除历史确认而不漏记启动期间的新写入。显式 `mark` 再设置本次点击起点。C 写入记录只保留请求号、结果类别、安全异常类型、errno 和耗时。

[准备阶段记录](plans/app-direct-lan-preparation-validation.json)保留当时的 NAT、管理员待操作、未点击 App 等状态；它不是本轮最新状态。该阶段曾保留 136 条历史确认，并验证两个新 HA 轮次都从零次 HA 调用和 C 确认开始。本轮继续使用这一观察器，没有修改生产运行代码。

## 临时桥接与恢复

[ha_macos_lab_lan.sh](../tools/ha_macos_lab_lan.sh) 的管理员实际运行路径已验证。使用 `socket_vmnet` v1.2.2 arm64 官方产物，固定摘要为：

```text
archive: c7bf62308fbcfdc29bdfb8373c9b1951f7ac2396446e4390919796a94972e6dc
binary:  b8a72a62237312f2f756027dea504a844edeb40014702d4a320292c026d282b0
```

脚本在 root 管理的临时目录启动桥接，不写 sudoers、不安装常驻服务。本轮在所有实验所有者停止后才应用 Lima 配置；只启动一个使用该配对身份的 SDK。发现端口使用 5683，本地认证控制端口仍是 5686。实际端口和接口只改独立运行目录，未改根、子 SN 或家庭路由器。

测试结束已确认：

- 平板恢复原 DHCP，界面读回 DHCP，IPv4 外网重新可达；临时熄屏时间恢复。
- Linux 的临时 IPv4／IPv6 防火墙链全部删除，实验 HA 和 SDK 停止，原生所有者为零，配对资料未变。
- 实验容器停止，原运行配置恢复；Lima 原 YAML 按备份摘要恢复，虚拟机回到初始停止状态。
- 用户终端中的 root 桥接助手仍需按 **Ctrl-C** 清理；本轮不把这一项记为已完成。它已没有运行的实验虚拟机连接。

依赖说明见 [Lima VMNet 文档](https://lima-vm.io/docs/config/network/vmnet/)、[socket_vmnet v1.2.2 源码](https://github.com/lima-vm/socket_vmnet/tree/v1.2.2)和[官方 Release](https://github.com/lima-vm/socket_vmnet/releases/tag/v1.2.2)。

## 后续验收

1. 准备同时排除平板 IPv4、IPv6 云端回退的独立网络条件，保留 LAN 调试；先验证隔离确实生效。不能只靠 IPv4 网关变化推断完全断网。
2. 冷启动 App，核对同一实验根、子身份，记录配对后本地发现与认证协商。对照原生旧 SDK 的发现声明和协议入口，有实际差异后再决定兼容补丁。
3. 重新建立虚拟灯关闭、其他灯效、零写入的 HA 冷启动基线。只点击一次空场景，要求实际 App LAN 请求、一次 HA 调用、一次 C 确认和正确读回同时成立；再用新 HA 进程验证恢复及第一次后续控制。保留所有首个失败。

`app_direct_lan_verified`、`empty_scene_first_control_verified` 和 `app_LAN_restart_verified` 继续为 false。生产接管保护不解除，未重打 b8 安装包，未 push 或创建远端 MR。

完整改动范围见[改动清单](change-inventory.md)。Jev 本轮只分类“发现”“未到后端”“云端对照”等证据范围；身份、包计数、写入次数、状态和通过条件由确定性检查负责，组件没有新增 AI 运行依赖。

## 实验设备清理（2026-10-22）

按用户明确要求，从真实智慧生活 App 删除了四台实验网关：`TEST-SingleEngine-A`、`TEST-Legacy-B`、`OpenHarmony C 实验`、`独立桥接实验`。另外逐张删除 22 张未自动移除的实验子卡，包含两轮遗留风扇、辅助开关、定时、灯光设置、灯效和早期书房实验卡；随父网关自动移除的子卡不计入这 22 张。

每次删除前读取 App 设备信息，以实验资料中的完整 SN，或已知实验父 SN 与源码固定算法生成的子 SN 精确核对。最早的旧 SDK 网关同时核对原实验记录的 SN 和 MAC；没有按名称相似、离线状态或照明数量差值直接删除设备。

最终重新启动 App 后，首页显示照明 **32** 个，只保留原来的 **一个智控网关**。原 HA 清理前后的只读诊断确认：同一个已加载桥接条目、同一个 HA 进程、旧后端、原来的 32 个设备及全部服务绑定一致，旧 SDK 云端在线回调正常。本轮没有向原 HA 发出设备控制，没有升级、切换或重启 HA，也没有修改米家自动化。

所有已知实验 VM 均停止；临时 Mac 桥接助手也已退出。截图、逐项身份核对与删除审计仅留在本地私有清理目录。旧配对文件只作为离线证据保留；后续独立实验须使用新的临时身份并重新配对，不能假定上述已删除云端身份仍有效。
