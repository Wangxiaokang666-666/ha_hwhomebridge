# b9 安装、升级、回退与四键 App 验收

2026-10-22。本轮没有访问、安装、启停或切换原 HA，没有操作家庭灯光或米家自动化。全部 HA 操作在独立 ARM Linux / HA Core 2026.10.1 内完成。

## 交付物

本地保留式升级包为 `hwhomebridge-1.1.0b9.zip`，包含 60 个载荷文件，SHA256：

```text
f288fdf0868f2321834ae2469d70935cc839faf6cc1a6c3f71750f96598536b0
```

源码基线是 `2c6a3ae`，包内组件版本更新为 b9；每个实际载荷均有单独哈希。已逐字节核对设备管理、角色绑定、四键布局和 profile 校验模块，以及两种架构的 C 程序与当前源码构建相同。原生程序包含按 Content-Length 读取确认、共享原 KV 路径的身份探针修复。

这仍是**已有原项目安装目录的保留式升级包**，不含原 `config/`、闭源 SDK、私有 profile、配对资料或家庭配置。它不能单独作为空白 HA 的完整 HACS 安装包使用。原项目的安装目录和必要资料应先准备好，再安装此包；不能把实验夹具的私有目录当作生产资料。

安装工具的 `--config` 必须指向独立测试目录，容器须停止。预检、备份、安装和还原继续使用 [原安装工具说明](openharmony-installation.md)的流程，替换为 b9 包和上面的已核验哈希。安装仅更新组件，不会自动更新 `.storage` 中的原生程序、启用引擎或解除生产接管保护。

## 已通过的实际验证

| 项目 | 实际结果 |
| --- | --- |
| 安装前基线 | 原 b8 源码在真实独立 HA 加载；只有一个条目，后端停用，身份文件保留 |
| b8 → b9 | 实际包经预检、备份、文件安装后启动 HA；原配置、库、profile 和条目保留 |
| 安装失败 | 在文件替换位置注入一次失败；组件和条目完整恢复，随后正常安装成功 |
| b9 设备管理 | 从实际包加载设备选择、角色和布局；跨设备绑定拒绝，标准灯新增与四键服务写入、读回通过 |
| HA 冷启动 | 新 HA 进程恢复同一条目、配置及子 SN；原配对 KV 和冻结身份未变 |
| 重复升级 | b9 再次安装通过，失败注入保护仍有效；随后 HA 正常加载 |
| 回退 | 还原重复安装备份，再还原最初 b8 备份及该集成选项；真实 HA 加载 b8，同一条目和身份保留 |
| 新 App 夹具 | 全新独立 HA 目录按原项目所需本地资产加实际 b9 载荷组装；新生成未配对身份，仅预置一个停用条目，产品/profile/两张四键卡目录校验通过，SDK 所有者数为零 |

上述维护容器均使用 `--network none`。已有身份副本只作为离线读写、安装和还原证据，不曾用已删除的实验身份重新上线。公共测试 96 项、工具测试 125 项通过。原生 x86 硬件验收仍未完成，本轮不能据此新增该结论。

## 智慧生活 App：尚未开始实点

旧 MatePad 调试地址未连通；当前连接的 `MOR-M1` 是其他设备，没有替代 MatePad 操作。临时 LAN 桥接 socket 尚不存在，管理员助手仍需用户在本机终端输入密码启动。因此本轮还没有执行发现、配对、八个分键点击、App 重启读回或删除云端测试设备。

新身份当前 PIN 已失效、后端停用，没有启动云端 SDK，没有新增云端测试设备，暂时没有需要删除的云端测试卡。已经清理的旧实验身份继续保留离线，不作为可配对身份使用。

后续接续顺序：

1. 确认 MatePad 型号、调试地址、解锁及智慧生活前台状态；启动临时 LAN 助手，检查实验 Linux 获得实际 LAN 接口。
2. 使用本轮**新的**临时身份刷新 PIN。只启动一个 SDK，配对前后记录根、两张四键卡和内建虚拟探针的精确 SN/云 ID，建立清理白名单。
3. 在 App 中逐张核对身份并命名。两张卡分键分别验证 1–4 档、5–6 档、自然风、电源；两个总开关均验证风扇电源。每次点击前标记审计，要求一次相应 HA 调用、C 接受和真实状态读回同时成立，未选档位的关闭不得误停其他档。
4. 用新的 HA 进程验证同一根与子身份、App 状态恢复和重启后的第一次控制。保留失败记录，不用后续成功覆盖首次失败。
5. 停止 SDK 后，只按白名单精确删除本轮虚拟子卡和根网关，检查无残留，再恢复平板设置、临时网络及 VM 初始停止状态。整个过程不得按通用卡片名称猜测家庭设备。

新增 `prepare_four_key_app_fixture.py` 从实际包准备新夹具；`four_key_app_acceptance.py` 提供虚拟实体、真实 HA 服务、SDK 确认审计、独立轮次和启停通道。它们只是实验工具，不提供第二套生产网关，也不构成 App 验收通过证据。

机器可读边界见 [b9-package-validation.json](plans/b9-package-validation.json)。原始备份、日志、身份和 PIN 留在仓库外私有目录。Jev 仅对文件安装、App 控制与身份清理材料分类，未参与身份认定或通过判定。
