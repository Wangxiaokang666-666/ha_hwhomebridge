# 同一网关的设备选择与角色绑定

2026-10-22，本轮实现在 `codex/openharmony-ha-integration-plan`。只验证独立 ARM Linux / HA Core 2026.10.1，没有安装、切换或重启原 HA，没有控制真实灯光、风扇或修改米家自动化，也没有重新配对已经清理的实验云端设备。

## 使用入口

在原集成条目点击“配置”：

1. **设备管理**：勾选 HA 来源设备。已接入设备可启停；新增设备继续选择功能卡并绑定实体。同名设备显示型号或短标识，便于区分。
2. **角色绑定与功能卡片**：选择已配置设备，选择风扇布局、功能卡和对应 HA 实体。实体选择器只显示该来源设备下未禁用的实体，不能跨设备或重复绑定。原主灯的绑定不可替换。
3. **确认**：先显示来源数量、活动及保留子卡数量和模板限制，勾选确认后保存。任何校验失败均不保存选项；另一个配置页已经保存时，旧页面必须重新打开。

管理配置保存在原条目的 `options.gateway_devices`，同一次保存更新配置修订号并重载原条目。它沿用当前引擎选择；引擎原本停用时仍保持停用。配置和重载不调用家中实体的开关、风速或定时服务。

当前可新增已有组合适配器支持的设备，以及支持亮度、色温的标准灯。没有经过安装预检的 PID/profile 不会出现在可用卡片中；纯开关灯、彩色灯或其他新类别不能据此视为已经支持。

## 保留与停用规则

- 原父身份、原条目、旧设备 SN、冻结绑定和原配对 KV 保留，不创建第二个网关。
- 原来的普通设备仍使用冻结绑定；本轮没有开放任意修改旧 001–008 绑定的功能。
- 取消勾选表示停用桥接，不会关闭 HA 实体，也不等于从智慧生活删除卡片。已配对的卡保留身份并报离线，重新启用沿用原 SN。
- 未配对的停用候选不会送入 SDK，避免生成无用云端卡片。更换布局时，旧的已配对布局保留离线；是否在智慧生活删除由用户决定。
- 新增标准灯按原设备 ID 生成稳定 SN；补充卡按父身份、来源设备和固定卡键生成身份。重启、重新选择和列表排序不改变它们。

有管理选项时，运行目录使用 `runtime/managed/` 的活动目录与子卡状态。其 `sdk-state` 仅指向同一网关原有的 `../sdk-state`，不复制或重建账号资料。旧冻结目录仍是安装、迁移和身份校验的输入。原配置尚未启用管理层时继续使用原运行目录。

## 智慧生活模板整理

| 选择 | 实际能力与限制 |
| --- | --- |
| 原风扇模板 `28BF` | 保留兼容，但云端页面仍显示七／八档和摇头等本型号无效入口 |
| 六档开关卡 `2151` × 2 | 八个分键对应一至六档、自然风、电源；两个卡的总开关也控制风扇电源。退出未选中的档位不会误停另一档，关机后不因残留百分比显示某档已选 |
| 原主灯 | 沿用原卡及绑定，保留开关、亮度、色温；不会另建替代主灯 |
| 方向、氛围灯、灯光设置和灯效 | 按需勾选；方向沿用已修复的厂家极性，灯效须由实际实体声明支持 |
| 完整原生定时 `2NAL` | 保留设备原生 enable/duration/remaining 控制；厂商页面仍有未映射入口，选择页和确认页明确提示 |

这不是修改华为云端页面或删除 profile 字段。四键布局的按钮槽位和 HA 路由已验证；智慧生活中最终显示、命名、语音和场景联动仍需在后续有明确范围的 App 验收中确认。此次未创建任何新的云端测试设备，不能把 HA 表单或虚拟路由测试记作新版智慧生活页面验收。

## 安装前提

这是受管单网关的配置入口，不能靠打开选项直接接管常驻旧 SDK。仍须按照已有维护计划离线准备原网关目录，并以当前源码重建原生程序。

`tools/ha_gateway_prepare.py` 现在产生 `managed_catalog_protocol: 1`。旧目录没有该声明时，设备管理入口会提示先更新资料，不保存管理配置。C 启动代码支持共享 KV 目录，在任何 SDK 网络启动前继续校验根身份。安装预检和运行预览共用 profile 校验，防止产品、服务类型、特性和范围不一致。

生产目录继续保持 `offline_preparation: true`，本轮不解除该保护。后续已将当前界面和 C 修改打入 b9 保留式升级包，并完成独立安装、重复升级和 b8 回退；见 [b9 验证记录](b9-package-and-app-acceptance.md)。智慧生活新布局仍待物理 App 验收，生产目录和接管保护保持不变。

## 本轮验证

公共测试 96 项、工具测试 125 项通过，配置校验和 Git diff 检查通过；ARM64 与 x86_64 Linux 静态构建通过。ARM Linux 实跑 CoAP/TLS 编解码回归和 SPEKE 自握手通过。x86_64 仅有交叉构建证据，本轮没有原生 x86 硬件验收。

真实独立 HA 中，`gateway_management_acceptance.py` 验证六个原生配置步骤、EntitySelector 序列化和跨设备拒绝、添加标准灯、六档卡服务写入和读回、保存重载、并行表单冲突、停用后零写入、未配对停用候选不注册，以及新 HA 进程的配置和 SN 恢复。冻结身份资料和 KV 内容保持不变。

容器使用 `--network none`，选项中的后端保持 `disabled`。实际 C 程序验证共享 KV 身份后，在预设的无效网络接口处拒绝继续，未启动云端 SDK。这证明本轮身份读取路径可用，不是云端在线验收。

浏览器验收使用同一离线 HA 的原生前端，检查设备选择、布局、功能卡、角色实体选择及确认页；临时访问通道只连该容器回环 HTTP，不承担任何生产桥接业务。

公开的机器可读结果见 [ha-device-management-validation.json](plans/ha-device-management-validation.json)。截图、完整收据、配置和调试日志保存在仓库外私有实验目录，不进入贡献提交。
